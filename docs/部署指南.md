# 部署指南

## 路径 A：本机直接运行（当前环境，零 Docker）

1. MySQL 8.4 已装于 `C:\Program Files\MySQL\MySQL Server 8.4`，数据目录 `D:\mysql-data`（用户态运行，无需管理员）
   - 启动：`scripts\mysql_start.bat`（mysqld 自动转入后台，关掉 bat 窗口不影响）
   - 停止：`scripts\mysql_stop.bat`（root 密码自动从 `backend\.env` 的 `MYSQL_ROOT_PASSWORD` 读取，不在仓库中）
2. 后端：`cd backend && venv\Scripts\python run.py`（默认 127.0.0.1:8000，**单 worker**——Chroma 嵌入式 SQLite 锁限制）
3. 前端：`cd frontend && npm run dev`（5173，/api 已代理）
4. 缓存：`.env` 的 `REDIS_URL` 留空 → 自动降级为内存语义缓存，功能不缺失

## 路径 B：Docker Compose（MySQL + Redis）

有 Docker Desktop 时：

```bash
docker compose up -d          # 启动 MySQL 8 + Redis 7（含自动建库 init.sql）
cd backend && venv\Scripts\python run.py
```

`.env` 配置 `REDIS_URL=redis://127.0.0.1:6379/0` 启用 Redis 语义缓存（跨进程共享）。

## 生产部署要点（答辩可讲）

- 前端 `npm run build` 产出 `dist/`，由 Nginx 托管并反代 `/api` → 后端
- **Nginx 必须关闭 SSE 缓冲**：
  ```nginx
  location /api/chat {
      proxy_pass http://127.0.0.1:8000;
      proxy_buffering off;
      proxy_cache off;
      proxy_set_header Connection '';
      proxy_http_version 1.1;
      chunked_transfer_encoding off;
  }
  ```
- 后端可套 systemd/任务计划程序自启；uvicorn 保持单 worker（或迁移 Milvus/独立 Chroma 服务后多 worker）
- JWT 密钥与数据库口令放环境变量，`.env` 不进版本库

## 从零恢复演练（数据兜底）

1. 删除 `backend/data/chroma/` 目录（模拟向量库损坏）
2. 重启后端 → 管理后台对每个文档点「重建索引」
3. 问答恢复正常（向量全部由 MySQL chunks 表重新生成）
