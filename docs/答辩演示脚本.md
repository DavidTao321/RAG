# 答辩演示脚本

> 演示前准备：`mysql_start.bat` → 后端 `run.py` → 前端 `npm run dev`，浏览器开 http://127.0.0.1:5173

## 场景一：多用户与权限（1 分钟）

1. 用 `admin/<backend/.env 中的 ADMIN_PASSWORD>` 登录 → 展示左侧头像下拉菜单有「知识库管理」入口
2. 退出，注册一个普通用户（如 demo1）→ 登录 → 菜单中**没有**管理入口
3. （可选）直接在浏览器访问 http://127.0.0.1:5173/admin/documents → 被路由守卫弹回问答页

**讲解点**：前后端双重 RBAC；JWT + bcrypt；token_version 机制（改密即全端下线）

## 场景二：知识库管理（1.5 分钟）

1. admin 进入管理后台 → 文档管理：21 个文档、状态标签（待处理→解析中→已入库）
2. 上传一个新的 Excel 商品表 → 2 秒内变「解析中」→ 自动轮询变「已入库」
3. 打开「分块预览」展示分块效果（键值对行组保留列语义）
4. 删除一个文档并说明：Chroma 向量 + MySQL 分块 + 磁盘文件一并清除

**讲解点**：异步入库状态机；Excel 行组切分策略；chunks 表为事实源、可重建索引

## 场景三：RAG 问答与引用（2 分钟，核心）

1. 问「星耀X90 Pro的电池容量是多少？首发价多少？」→ 逐字流式输出
2. 回答内 **[1] 编号可点击** → 右侧引用面板高亮来源文档名 + 片段原文 + 相关度分
3. 追问「它支持快充吗？」→ 展示多轮指代消解（检索 query 拼接上文）
4. 问「iPhone 99 多少钱？」→ 回答"知识库中未包含该信息"，不编造

**讲解点**：混合检索 + RRF + qwen3-rerank；引用编号映射机制（模型标注 → 后端提取实际引用 → 前端联动）

## 场景四：多会话与历史恢复（1 分钟）

1. 新建 3 个会话问不同品类问题 → 左侧列表互不干扰
2. 重命名、删除会话
3. 刷新页面 / 退出重登 → 会话与历史消息完整恢复，引用快照仍在

**讲解点**：会话数据模型（user→conversations→messages）；历史分页加载

## 场景五：性能优化演示（2 分钟）

1. **同问题二问**：第二次回答旁出现「缓存命中」标签，耗时从 ~5s 降到 ~200ms（右上角毫秒数对比）
2. 连续快速提问 21 次 → 第 21 次返回 429「请求过于频繁」（限流）
3. 数据看板 → 性能指标：平均检索 190ms / 重排 217ms / 生成 776ms / 缓存命中率
4. 问答趋势图（含缓存命中量曲线）

**讲解点**：语义缓存（余弦≥0.92 + kb_version 失效）；限流防配额击穿；分段耗时统计体系

## 场景六：数据兜底（30 秒，可选）

删除 `backend/data/chroma/` 目录 → 重启 → 管理后台「重建索引」→ 问答恢复正常
